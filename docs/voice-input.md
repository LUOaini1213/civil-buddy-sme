# 语音输入

工地上的人常常戴着手套、手里拿着图纸或卷尺，打字不方便。工作台输入框左边的「语音」按钮，可以把一句话说出来、转成文字。

## 交互：只回填，不发送

1. 点「语音」开始录音，按钮变成「停止 0:05」计时；再点一次就停止。一段最长 20 秒，到 19 秒时自动停止。
2. 识别出的文字**接在输入框已有内容的后面**，光标停在末尾。
3. **不会自动发送。** 下方状态行写明「请核对后再发送」。人看过、改过之后，自己按发送。

这样设计是因为语音识别会出错，而工作台的下游（装柜计算、投标响应、签认草稿）对错一个词并不宽容。评测里实际出现过「平柜 → 瓶柜」「订舱 → 订仓」这类错误。所以核对这一步留给人来做。`demo/tests/test_voice_js.py` 在一个假页面里驱动 voice.js，检查它除了自己的四个元素之外，不碰页面上任何别的东西（发送键、表单、按键事件都不碰）。

## 识别从哪里来

| 场景 | 用什么识别 | 录音去哪里 |
|---|---|---|
| 统一 Rust 工作台的 Python 环境，或独立 Python 工作台已安装 `requirements-asr.txt` | **本机 faster-whisper**（默认 `small`，CPU int8），中文使用土木术语表，英文使用英文提示 | 音频只在本机内存里解码，请求结束即丢弃，不写盘；模型文件另存于缓存目录 |
| 本机识别缺少依赖、模型准备失败，或在运行中出错 | 浏览器自带识别（Web Speech API） | **发送到浏览器厂商的服务器**（Chrome 为 Google）。首次使用前弹窗说明，同意后才开始；涉密或内网项目请不要使用 |
| 两者都没有 | 按钮置灰，并说明原因 | — |

页面通过 `/api/asr/status` 判断用哪一种。只有「本机可用」这个结论会被记住；选了浏览器或不可用时，每次点击都会重新探测，所以装好本机识别之后，下一次点击就会用上。本机识别返回 5xx 时，本页之后改走浏览器识别，并且照样先征得同意。

## 模型准备：先准备好，再录音

第一次使用默认会下载 Whisper `small` 模型（约 460 MB）。准备在后台进行，**不在识别请求里做**：页面先查询 `state`，模型没就绪时调用 `/api/asr/prepare`，并显示「下载好之前先不录音」，然后轮询到 `ready` 才开始录音。统一 Rust 工作台用固定子进程准备模型，每次转写只能读取已缓存模型；独立 Python 工作台用后台线程。等待时可以点「取消」，后台准备会继续。准备失败时页面会说明原因，再次点击可在用户同意后改用浏览器识别；独立 Python 服务另有 5 分钟失败重试间隔。

## 术语表

`demo/asr_lexicon.txt` 收了 35 个术语（装柜物流、投标、施工结构、造价合同、安全签认），和一句领域说明一起放进 Whisper 的 `initial_prompt`。

两个硬约束写在代码和测试里：

- **提示上限 223 token。** faster-whisper 会把超出的部分**从头部悄悄截掉**。第一版 45 个词实测 273 token，排在最前面的「箱单、高柜」根本进不了模型。所以现在只收最容易被听成日常词的术语，当前 222 token。
- **一段最长 20 秒。** CTranslate2 每个 Whisper 窗口最多生成 224 个 token，时间戳也算在内，这个上限和提示长短无关。中文大约每个字 1.4 token，语速快时每秒 6 个字，20 秒约 170 个文字 token，加上时间戳还在上限以内。之前定的 30 秒，说得快的人会超出上限，这时要么尾巴被丢掉，要么进入第二个窗口，而第二个窗口的提示里已经放不下完整的术语表。长内容请分几段说，文字会依次接在后面。
  - 页面在 19 秒时自动停止，后端另外留 2 秒宽限：后台标签页的计时器可能晚触发，编码器也会补帧，落在宽限内的录音会被裁到 20 秒，而不是整段拒掉。

词表修好了什么、没修好什么，以及领域说明和术语表各自贡献了多少，见 [eval/asr](../eval/asr/README.md)。

## 接口

- `GET /api/asr/status` → `{available, state, engine, model, loaded, load_error, lexicon_terms, max_seconds, stores_audio: false, reason}`，其中 `state` 取值为 `ready | loading | cached | missing | failed | unavailable`
- `POST /api/asr/prepare` → `{state}`。在后台加载模型，首次使用时会先下载；引擎不可用时返回 503
- `POST /api/asr`：请求体是原始音频字节（MediaRecorder 录的 webm/ogg/mp4，或 wav），返回 `{text, engine, model, audio_seconds, elapsed_seconds, lexicon}`。**只返回文字**：不调用大模型，不建会话，不写文件。
  - 400：空录音、格式不在允许范围内、无法解码、短于 0.3 秒，或超过 20 + 2 秒
  - 409：模型还没就绪（同时会开始准备）
  - 413：超过 8 MB（请求体按流式读取，超出就停止）
  - 429：另一段识别占用超过 60 秒
  - 503：引擎没装、装了但原生依赖加载失败、模型加载失败、运行中出错。页面遇到 5xx 会改走浏览器识别
- `/api/health` 的 `capabilities.asr` 与 status 用的是同一个探针，所以两边结论一致

识别串行执行，同一时间只跑一个，免得占满一台笔记本的 CPU。`elapsed_seconds` 只统计识别本身的耗时，不含排队时间。

## 解码的安全边界

请求体会交给 FFmpeg（PyAV）解码。它能识别的格式很多，其中有些格式会访问网络或读取本地文件：比如 SDP 会按对方指定的端口监听 UDP，concat 会去读本机文件。所以解码前后有这几道关：

- FFmpeg 只允许从内存管道读取（`protocol_whitelist=pipe`），SDP、concat 这类请求体会被直接拒绝
- 容器格式必须是 MediaRecorder 会产出的几种（webm/matroska、ogg、mp4、wav）之一
- 按每一帧自己的采样率累计时长，超过 22 秒立即停止；采样率必须在 8–192 kHz 之间。这样，一个只有 60 KB、却在文件头里谎报 20 Hz 采样率的 WAV，不会在重采样到 16 kHz 后膨胀成几百 MB

以上几条各有一个测试；另外还用变异测试确认过：把这些守卫逐条删掉，对应的测试都会失败。

## 启用本机识别

```bash
pip install -r requirements-asr.txt
cd demo && uvicorn app:app --host 127.0.0.1 --port 8765
```

可以用 `CB_ASR_MODEL` 换模型；换了之后需要重跑 `eval/asr`，并重新核对提示长度。

统一启动器支持从环境变量或显式选定的 `--env-file` 读取 `CB_ASR_MODEL`、`HF_HOME`、`HUGGINGFACE_HUB_CACHE` 和 `XDG_CACHE_HOME`。后面三项用于选择本机缓存位置；本次统一服务验收通过 `HF_HOME` 指定任务独立缓存。更改后需要重启工作台。模型 API Key 和 Hugging Face Token 不会作为环境变量传给语音服务；这里使用公开语音模型，不需要填写语音密钥。

浏览器只在 `http://127.0.0.1`、`localhost` 或 `https` 下才允许网页使用麦克风；用局域网的 http 地址打开工作台时，按钮会提示这一点。

## 2026-09-30 统一服务实测

在 Windows 独立环境中，通过实际 Rust HTTP 入口与固定 Python 语音进程下载并运行默认 `small` 模型。模型准备耗时 48.6 秒；两个中文合成音频和一个英文合成音频均返回转写，HTTP 总耗时分别为 5.14、4.78、4.08 秒。英文句子完整识别；中文仍将「箱单」识别为「相单」，因此结果必须由用户检查，不能把这三例当作现场准确率。

实际取消请求回收了识别进程，原请求返回 409，服务随后恢复空闲。转写前后 Agent 任务列表均为空，没有新增业务交付文件，三个输入音频的 SHA256 不变。状态目录未发现音频文件；这与音频只在内存中处理的实现和回归测试一致。这里验证的是合成音频 HTTP 链路，没有使用真人麦克风。

本轮还修复了启动器丢失显式语音模型和缓存配置的问题，以及英文界面中已知语音错误仍显示中文的问题。未知错误细节、原始文件名和转写文字保持原文。启动器 12 项、语音前端 23 项、语言切换 4 项回归通过。

## 没做的

- 没有用真人现场录音评测，评测音频是两种 Windows 合成音色（见 eval/asr）。口音、方言、工地噪声下的表现都没有量过。
- 浏览器识别这条路没有评测：它依赖厂商的在线服务，没法离线复现。
- 没有同音纠错。评测里剩下的错误几乎都是同音词（订舱 → 订仓、平柜 → 瓶柜），提示对这类错误推不动。
- 没有语音合成（把回答读出来），也没有唤醒词。
- 统一 Rust 工作台通过固定 Python 领域服务接入本机识别，并保留需用户同意的浏览器识别后备。需在同一 Python 环境中安装 `requirements-asr.txt`，再在页面明确准备模型；缺少依赖或模型时显示不可用。转写只进入可编辑草稿，不自动发送。本轮未以真人麦克风验收。
