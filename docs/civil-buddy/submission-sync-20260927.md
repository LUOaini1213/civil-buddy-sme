# 比赛提交前的本地遗漏核对

目标仓库：[civil-buddy-sme](https://github.com/LUOaini1213/civil-buddy-sme)。核对起点为 `7e3a53b`。

本轮检查了旧项目登记的 80 个工作目录及 58 个本地分支。新仓库工作目录干净，
不代表旧分支和旧工作目录中的功能全部迁入。49 个分支已经完整进入新仓库；其余分支按具体代码核对，
没有直接合并早期快照、备份分支或覆盖新的权限实现。

## 补入内容

| 来源 | 补入能力 | 说明 |
|---|---|---|
| 旧仓库板块清单分支 | 标题行、多行表头、Mark / Nos / Wt / Depth、吨单位与成对尺寸；记录来源行和未读列 | 保留合成混合板块样例，多个任务的解析记录隔离 |
| 旧仓库 Web 分支 | 招标文件与箱单双文件上传、英文 `/demo`、修订后失效陈述与来源哈希 | Python gateway 的口令入口；不是 Rust 同一进程多租户功能 |
| 旧仓库部署分支 | Lightsail 部署脚本、口令轮换、显式模型配置与本地容器演练 | 脚本目标已换新仓库；提供脚本不代表完成云部署 |
| 旧仓库模型分支 | 完整 API 地址规范化、可选择的端点评测、每柜货重与毛重 | 回归使用本地脚本模型；真实端点评测会消耗额度，需操作者另行明确运行 |
| 旧分支及本地修复 | 空格千分位重量、吊装与集装箱限重区分、分号后的限重、明确否定联动、合成标记误判 | 保留上限/下限和资料注入防护 |
| 本地招标工作目录 | 前附表未归类行保留；Rust 招标提取读取当前会话原附件全文 | 原附件读取失败须明确报告；保留原文件和会话边界 |

旧报名正文草稿仍有历史产品口径，不作为本次正式报名材料覆盖。研究工具工作目录中的功能已经在新仓库；
临时评审脚本、生成报告、真实业务资料、凭证和运行数据库不随代码发布。

## 启动和交接

桌面浏览器工作台按[统一启动说明](unified-workbench.md)运行。独立的网页双文件演示在 Python gateway 的
`/demo`，其部署步骤见[最小部署说明](../deploy-minimal.md)；它不自动成为 Rust 页面的新入口。
交给同学时使用本轮明确版本的发布包和 [SHA-256 / 验收表](acceptance/sme-preview-checklist.md)，
不要把旧电脑上的未同步目录当作提交版本。

## 验证口径与剩余边界

每次提交的 CI、发布包验证记录与实际运行日志分别保留，不能用旧版本的通过数替代本次结果。
迁入的历史封存测试已用于开发和回归，本轮不再声称它们是未见过的独立测试集，也不修改原始标准答案来提高分数。

板块封存集的原有下限通过不等于 6 份全部正确：目前精确结果 4/6、安全行为 5/6。
包含 stillage 的混合表仍需人工核对包装和货物角色；带封面工作表的文件需要选择正确的数据表。
通用招标解析也仍保留幕墙条款覆盖缺项。真实图纸仅使用明确尺寸，缺少拉伸长度不生成模型。
真实工程、同事第二台电脑、Office 渲染、真实付费模型和公网部署均需各自的验收证据。
