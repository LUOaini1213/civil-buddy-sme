# 工程工作台：学校比赛运行与演示

本轮把 CAD 截面性质、梁/框架分析、施工甘特图、IFC 检查与版本对比接入现有工作台。计算由确定性库执行，用户提供参数，页面负责展示、修改和保存。研究清单中其他候选仍是后续项目，不能当成已集成功能。

核验日期：2026-09-21。专项测试已通过分析记录 12 项、实际 IFC/IDS 库 9 项、HTTP/子进程整合 8 项、梁分析 16 项、工程 UI 14 项、CAD UI 51 项、CAD Agent 8 项（含真实求解器与离线模型）。梁、截面、IFC 与甘特浏览器验证见下方记录。最终 `npm run check` 102/102 与指定六组深度检查 6/6 全通过；交付 ZIP 的 843 个文件清单与摘要已核验，包内梁求解器实际算得总反力 4000 N。真实工程输入仍待验收，不能由合成样例替代。

## 安装与启动

在项目根目录使用 Python 3.11 或适配这些固定版本的更新环境。已安装主项目的同事只需补第二条依赖命令。首次安装会访问包仓库；四类计算不需要配置大模型或发送图纸到模型服务。

```powershell
python -m pip install -r requirements.txt -r requirements-cad.txt
python -m pip install -r requirements-engineering.txt
python -m packing_assistant.civil app --port 8767
```

如果已有其他虚拟环境，先激活项目实际使用的环境，避免装到另一个 Python。`requirements-engineering.txt` 固定 PyniteFEA 3.2.0、sectionproperties 3.10.2、IfcOpenShell/IfcTester/IfcDiff 0.8.5；传递依赖没有全部固定。保留演示机器实际安装版本记录，另一台机器应重跑验收，不能只凭依赖安装成功宣布结果一致。

入口：

- `http://127.0.0.1:8767/cad`：图纸与截面选区。
- `http://127.0.0.1:8767/engineering`：梁/框架、IFC 检查、IFC 对比与分析项目。
- `http://127.0.0.1:8767/engineering/schedule`：施工计划。
- `/api/engineering/capabilities`：本机依赖状态；缺依赖会返回未就绪，不制造成功结果。

沿用工作台既有访问口令、请求来源和写入权限检查。运行目录、端口及配置应与团队实际部署一致。

## 首批能力与边界

| 能力 | 当前输入与输出 | 当前限制 |
| --- | --- | --- |
| CAD 截面性质 | 已确认单位、材料区域和孔洞的 DXF 选区 → 面积、形心、形心惯性矩/积、主惯性矩、主轴方向与回转半径；保留原实体编号 | 不要求拉伸长度；不计算强度、扭转或翘曲。多块不相连区域分别计算。曲线结果对应记录的离散误差；等主惯性矩不虚构唯一主轴角 |
| 梁/框架 | 用户明确给出的节点、约束、材料、截面、荷载及组合 → Pynite 一阶弹性内力、位移与反力 | SI 单位 m/N/Pa/rad。没有自动从平面图猜跨度/支座/荷载，不是规范验算；不自动施加自重或荷载分项系数 |
| 施工计划 | 用户任务、日历日期、进度、依赖 → 可拖动甘特图；保存、重开、本地撤销与恢复上次保存 | 采用 Frappe Gantt 1.2.2。依赖可检查、显示箭头；不自动计算 CPM、资源平衡或把后续任务顺延。日期包含首尾两天 |
| IFC + IDS | 一份 IFC 和用户提供的 IDS → 逐项信息要求检查报告，失败实体编号/原因、输入摘要 | IDS 信息检查不等于几何碰撞、结构安全或全面规范审查。上游 IfcTester/IfcOpenShell 负责解释规则 |
| IFC 版本对比 | 两份同 schema 的 IFC → 按 GlobalId 对齐的新增、删除、改变、未变及来源摘要 | GUID 全换会表现为新增/删除，不猜构件配对。比较范围含空间对象；遵循 IfcDiff 默认规则排除 IfcFeatureElement（如开孔）；几何表示变化也可能产生差异 |

截面性质已接入 CAD Agent 的受限工具 `cad_section_properties`：仅在用户明确要求计算时使用已确认选集与单位，不补设计尺寸，不修改原项目；真实求解器及离线模型测试已通过。其他本轮工程工具仍通过参数面板与确定性动作操作，不能宣称全部已接统一 Agent。BCF 问题闭环、PySlope、混凝土截面、管网、点云、交通和碳核算仍按研究清单逐项排期。

## 建议演示顺序

1. **截面**：在 CAD 页上传获得授权的 DXF，确认原图单位、实体区域和孔洞。在构件截面模式计算截面性质。没有明确长度时只演示截面性质，不制造拉伸长度。把面积与已标注尺寸的解析结果核对，并展示来源实体编号。
2. **梁**：在工程页载入明确标注的合成直梁例，计算反力和挠度。解释例中参数来自演示数据；再用用户已确认参数修改。简支均布梁的解析核对为两端反力 `qL/2`、最大弯矩 `qL²/8`、最大挠度 `5qL⁴/(384EI)`，坐标/符号按页面结果约定核对。
3. **保存与恢复**：明确保存一次成功结果，修改后再计算并保存为新版本。停止并重启服务，从最近项目重开，核对输入、结果、版本与来源摘要。编辑或计算失败时，先前成功结果仍应可辨认，不能误标为新参数结果。
4. **IFC 信息检查**：载入合成 IFC/IDS 例。旧版墙缺少 Name，查看失败实体编号与原因；切到补全信息的新版再查。真实 IDS 应来自本项目已确认交付要求，不能把演示 Name 规则当成完整审图。
5. **IFC 差异**：比较例中的旧版/新版，展示新增与属性变化。换成授权真实 IFC 连续版本时，先确认相同 schema 和稳定 GlobalId。
6. **施工计划**：载入合成计划，修改一条日期或完成率、撤销、保存、刷新重开。展示依赖提醒；不把箭头当成关键线路求解结果。
7. **导出记录**：导出工程计算 JSON 前，按当前界面完整键入既有签认确认句 `我明白，将由持证人员签认`。这是用户确认记录，不是系统签发的工程合格结论；导出内容也不是重写后的 IFC 或三维 BIM 模型。

真实图纸只采用明确标注或用户确认的尺寸；缺失材料、荷载或边界条件时，保留缺项。为了展示而使用合成输入，必须在页面和讲解中都说明。

本轮浏览器实测记录：

| 场景 | 已观察到的结果 | 证据边界 |
| --- | --- | --- |
| 合成简支梁改参 | 均布荷载从 1 改为 2 kN/m，总反力 4000→8000 N、Mz 2000→4000 N·m、dy 2.08333→4.16667 mm；未应用的表单修改会锁定运行，撤销后 q 回到 1000 N/m，重开保存版本正确 | 合成梁的浏览器计算与状态恢复；不代替真实结构模型验收 |
| 合成 IFC/IDS | 检查报告显示 1 项 Name 缺失及对应 GUID；两版差异显示新增 1、改变 1；两种结果均成功保存 | 实际工具处理合成输入，不是已验收真实工程 IFC |
| 合成有孔截面 | 面积 3600 mm²，Ixx=Iyy=4920000 mm⁴，1 个孔；服务真正停止重启后，重新打开记录一致 | 无拉伸长度也能计算由 HTTP 测试证明；该次浏览器样例仍带合成默认 6 m，不称浏览器无长度验收 |
| 施工甘特 | 日期拖动可整次撤销；进度拖动后保存并刷新一致；390px 窄屏操作通过 | 日历计划编辑，不代表 CPM 或真实施工安排通过 |

## 保存与接口

工程分析项目保留成功运行的输入快照与结果，客户端通过 `run_id` 保存，不能直接提交一份自称成功的结果。重新打开会恢复该版本快照；历史版本不自动重新计算。原始 IFC/IDS 文件内容随分析快照保留，CAD 截面快照保留已解析文档及配置。

网页部署的分析记录位于 `demo/out/_engineering/`；施工计划位于工作台所用仓库根目录的 `.civil-buddy/out/engineering/schedules/`。这是网页适配器的实际目录，不能把它们混称为任意 CLI 工地目录。备份时保留相应目录；本轮未新增工程分析项目包导入/导出，已有 CAD 项目包功能与分析记录导出应分开介绍。

| 接口 | 用途 |
| --- | --- |
| `POST /api/engineering/frame` | 运行受限梁/框架模型 |
| `POST /api/engineering/section` | 对已载入 CAD 文档及确认配置计算截面性质 |
| `POST /api/engineering/ifc/check`、`/ifc/diff` | IFC + IDS 检查 / 两版对比 |
| `GET/POST /api/engineering/projects` | 最近项目 / 保存成功运行 |
| `GET /api/engineering/projects/{id}?version={n}` | 恢复指定保存版本 |
| `POST /api/engineering/export` | 经既有确认检查导出计算结果记录 |
| `GET/POST /api/engineering/schedules` | 最近施工计划 / 保存计划 |
| `GET /api/engineering/schedules/{id}`、`POST .../{id}/undo` | 重开计划 / 恢复上次保存内容 |
| `POST /api/engineering/operations/{id}/cancel` | 取消本次计算 |

分析项目采用原子写入、摘要校验和乐观修订号；损坏记录不能覆盖健康记录。冲突返回后重新打开最新版本或另存副本。当前上限为 100 个分析项目、每项目 20 个版本、单项目 64 MiB、分析总存储 512 MiB。施工计划最多 250 项任务、跨度 10 年，版本规则以该模块记录为准。

IFC 上传每份最多 8 MiB、IDS 最多 512 KiB；IFC 根对象上限 20000，IDS specification 为 1–100 条。XML 外部实体/DTD、无效或重复 GlobalId、截断 STEP 和跨 schema 对比均拒绝。计算在固定操作子进程内进行，默认 120 秒超时，可取消；这不等同于 OS 级网络或内存沙箱。

## 离线验证与四人分工

### 当前版本的严格求解器门禁（2026-10-12）

历史核验记录保留原日期和原版本，不能自动沿用到新包。当前新增的严格入口为：

```powershell
python scripts/native_engineering_acceptance.py
python scripts/native_engineering_runtime.py --binary workbench/target/debug/civil-workbench.exe
# 源码仓库也可通过检查矩阵选择该入口
python scripts/check_project.py --only native-engineering
```

使用已安装主项目、CAD 和工程依赖的解释器。门禁要求固定版本的 PyniteFEA、
sectionproperties 与 IFC/IDS 库，梁/框架、截面、IFC/IDS、工程 HTTP 四组均实际运行；
缺依赖、任何跳过或预期失败、少于现有 16/10/9/9 项测试均不算通过。
每次在 `output/native-engineering/` 创建新 JSON 报告，保留解释器与依赖版本、
相关源码哈希、逐项结果和证据边界；`--report` 可指定一个尚不存在的路径。

这些是合成资料上的实际库与工具子进程测试，不是获授权真实工程、跨电脑、
真实模型或持证人员签认的验收。Python 依赖安装成功本身也不算测试通过。

第二项额外验证登录后的 Rust 主入口 → 私有 Python 服务 → 实际求解器，再检查
分析保存、修订冲突、精确签认导出、两个具名账号隔离，以及真实进程重启后的原始输入和结果恢复。
它使用临时本机实例和合成资料，不配置模型；首次启动时缺库会失败，不允许把另一个
解释器上的已安装依赖算到当前实例。解压包将 `--binary` 改为 `bin/civil-workbench.exe`。

STEP 可选内核另装 `requirements-cad-step.txt`。以上两项加 `--with-step` 时，
严格专项额外执行 STEP 4 项测试并禁止 skip；主入口额外核对服务端签认导出、
实际文件重开、实体数、孔洞体积与包围尺寸。未指定该选项的 44 项工程测试不能算作 STEP 已通过。

测试不得接真实大模型接口。设置 `PYTHON_DOTENV_DISABLED=1`，使用项目环境执行 `npm run check`，再按本轮检查矩阵执行工程专项和完整回归。`scripts/test_engineering_ifc.py` 使用真实安装的 IFC/IDS 库，但图纸为合成数据；依赖缺失导致 skip 不能当作该功能通过。`scripts/test_engineering_records.py` 检查重启恢复、中断、并发冲突、损坏记录和路径边界。结构、截面、甘特专项与 HTTP/浏览器证据也必须一并保留。

本轮通过的深度检查命令为 `npm run check:full -- --only http-demo,runtime-api,office-job,pipeline,shadow-eval,rust`，共 6/6；其中 Rust 检查耗时 90.1 秒。与 102 项基础检查一起，覆盖当前检查矩阵全部 108 项任务。

## 署名与比赛边界

本仓库随包包含的第三方前端文件是 Frappe Gantt；Python 求解器通过依赖安装使用。当前实际版本、许可文本链接、cytriangle/Triangle 条件及 bcf-client 元数据差异见 [第三方说明](../../demo/static/engineering-notices.txt)，页面也提供此说明。

sectionproperties 的 MIT 不替代 cytriangle 的 LGPL 与 Triangle 原作者条件。IfcTester/IfcDiff 属于现有 IfcOpenShell 生态深化。bcf-client 0.8.5 安装元数据和源文件头的许可声明不一致，保留证据并待上游澄清，不能武断把全包定为某一种许可。非商业比赛仍按实际版本与分发方式履行条款。

团队的原创贡献可如实展示为：面向土木输入的受限适配器、参数与来源确认、统一页面、结果解释、版本恢复、取消和可复现验收。求解器算法、网格库、IFC 规则引擎和甘特控件应明确署名。比赛章程尚未提供，此文档不替团队确认原创性比例、开源复用或 AI 辅助是否符合赛事要求。
