# 2026-09-27 审查修复

本页描述 v0.7.0 之后的开发修复。比赛材料中的历史演示仍以 `v0.7.0` / `0c0e803` 为基线；不移动旧 tag，不把新开发能力归到旧版本。

## 箱单读取

- 明确为公斤的列不再被量级猜测覆盖。例如 `weight_kg=60000` 保持为 60,000 kg，由后续工具检查承载与装载约束。
- 重量必须是可识别的单一有限数值；`450/500` 等有歧义文本不再删除分隔符后拼成新数字，也不由另一重量列静默掩盖。
- Excel 数量、重量及尺寸的公式没有可用缓存值时停止解析，指出工作表及单元格。程序不计算任意公式；用户需重新计算工作簿或提供确认后的数值。联动网页回复也显示此原因。
- 正常数值、有效公式缓存、汇总行和既有合法表格规则继续适用。固定合成演示的原数值不因修复而重写。

## Agent 完成状态与模型地址

文档写入的最终摘要依赖本轮实际登记的副本和来源哈希。执行请求未产生副本、工具失败或预览尚未保存时，不能靠模型一句“Done”认定交付完成。普通解释性回复仍可使用模型文字；该修复不代表所有自然语言回答都通过完整数值溯源检查。

模型地址支持 base URL 与完整 `/chat/completions` endpoint，避免重复追加路径；配置不接受 query 或 fragment。

## 项目包与文档

损坏的 ZIP 压缩流统一返回可解释的输入错误，已有物流项目保持不变。现行协作、知识库和安全反馈入口改指向 `civil-buddy-sme`。历史 commit/PR 引用继续作为原始证据保留。

当前开发线已有 `/api/tender/link` 和 gateway `/demo` 上传入口，冻结版文档中的缺失说明仅适用于其历史基线。

回归使用离线合成输入和本地脚本模型。通过这些测试不替代真实图纸、真实箱单、真人模型或云端部署验收。
