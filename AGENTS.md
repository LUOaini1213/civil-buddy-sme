# Civil Buddy · Agent notes

- **This product is 土木版 Codex.** Host = Civil Buddy. Skills = 66 experts. Not an export pack for OpenAI Codex CLI.
- **Experts are skills.** One `SKILL.md` per post: `.agents/skills/<id>/SKILL.md`. Router: `.agents/skills/civil-buddy/SKILL.md`. Catalog (name+description) first; load full SOP only after `$id` or implicit match. Do not load all 66 into one prompt.
- Desktop: `civil desktop` / `python -m packing_assistant.desktop` — a Tk window over the same runtime. All behaviour lives in `desktop/controller.py` (no tkinter import, tested without a display); `desktop/app.py` only draws. Turns run on a worker thread, widgets are touched on the Tk thread only, and nothing modal may open on its own at start-up.
- CLI: `python -m packing_assistant.civil` (TUI) · `civil exec` · `civil app` · `civil mcp --pack construction` · `civil serve` (JSON-RPC on this harness, not openai/codex)
- **Job folder = workspace.** `civil init` writes `CIVIL.md` (the job's AGENTS.md: stated facts only, blanks stay `UNSPECIFIED`); run `civil` inside that folder or with `-C <dir>` and session state plus drafts live in `<job>/.civil-buddy/out`, not in this repo. `civil exec --jsonl` streams `thread.started → turn.started → item.* → turn.completed`; `civil status`; `civil resume --last`.
- **Legacy Python entry points: two ways to run a turn** (`--mode` / `/mode` / `CIVIL_AGENT_MODE` / `agent_mode` in civil.toml). `steps` (default): rule routing + the deterministic pipeline, never calls a model. `model`: the Codex loop in `runtime/model_loop.py` — the model plans, loads a skill, reads job files and calls `run_skill` / `pack_plan` / `tender_compare`. `auto`: model when configured and reachable, else steps. In this legacy Python model pipeline nothing the model writes reaches a deliverable (the pipeline gets the user's words plus the job files the model picked), and the reply passes `tools/number_provenance` (benchmark: `test/benchmarks/number_provenance`). Tool results given to a model are labelled text, not bare keys. Regression tests use a scripted model and remain offline. Separately authorized live acceptance must be explicit, isolated, and reported as live; never silently send regression fixtures to a real endpoint. In either mode a task that names a job file is read from it: a named packing list goes through the packing engine (`pack-plan.md`), a named tender document is what gets parsed. A model reply also passes `tools/verdict_guard` (benchmark `test/benchmarks/verdicts`, quote the held-out row): a stated verdict such as 可以订舱 or 符合招标文件的要求 gets one rewrite and is struck if it survives. `civil review <doc>` (`/review`) is the model-free check: numbers and clause numbers with no source in the job's material, plus verdicts the draft may not state. Civil Buddy's own Excel copies in the job folder's top level are recorded in `.civil-buddy/exports.json` and are never read back as material.
- Slash: `/skills` `/new` `/bg` `/threads` `/sandbox` `/approvals` `/confirm`
- Sandbox `read-only|workspace-write`. Approval `untrusted|on-request|never`. No danger-full-access (secrets/spawn stay denied). `--sandbox-backend os|auto` (`sandbox_backend`, `CIVIL_SANDBOX_BACKEND`) runs tool work in a worker the kernel confines (`runtime/os_sandbox`: Landlock+seccomp on Linux, Low integrity+job object on Windows; writes only under `<job>/.civil-buddy/out`); `os` refuses the turn when it cannot be had. Never claim network confinement on Windows or any confinement of reads.
- **Procedural memory ≠ user memory.** Skills are SOP. Session slots (`jurisdiction` / `project` / `P0`) live in `session.summary.json`. Do not invent a user profile.
- **Unified Rust workbench:** `scripts/start_unified_workbench.py` runs Rust as the sole generic agent runtime; fixed Python workers perform document/retrieval/engineering operations. Model-drafted prose and structured patches may reach new document copies after source selection, hash/old-value checks, numeric/reference verification, identical preview, sandbox authorization and verdict checks. Original files remain immutable. Final Rust replies currently have verdict checks; do not claim the legacy number-provenance check covers them. See `docs/civil-buddy/unified-workbench.md`.
- **Tools validate and compute; the model routes and drafts.** No hand-written xyz, N0, cabinet counts, clause numbers, or composite unit prices. Unconnected solver fields stay the literal `UNSPECIFIED`. `can_fit=false` is a failure.
- **High-risk write gate:** user must type `我明白，将由持证人员签认`. Chat/questions do not write.
- **Bids:** `submit_blocked=true`. Never assert 可以投标 / 可以开工.
- **Plugins are declarative** (`runtime/plugins.py`, `docs/civil-buddy/plugins.md`): SOP + form template + knowledge, `.md`/`.json` only, never code, never an MCP server. A plugin skill may not reuse a built-in id; an untrusted plugin's skills are all high-risk; trust is per user and keyed by content hash; templates fill `label: value` slots from the user's words only and may not state a verdict. Keep it that way — a plugin format that can run something is a different product.
- Regenerate skills: `python scripts/build_codex_expert_skills.py`
